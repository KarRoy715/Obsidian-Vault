专利图：需要理解空间结构、组件编号、箭头指向、连接关系等

五个边界框：节点、节点标签、文本，箭头、图片标签

**数据集：**

- 数据集名称：PatentDesc－355k
- 数据来源：
- 60k+美国专利文献中获得355k+专利图片，主要关注2004年之后的
- 数据特点：
- 图片描述：均值分别为34和1680 tokens，包括简洁和详细描述
- 简洁：0到100 tokens
- 详细：0到6,000 tokens

注：COCO、TextCaps、NoCaps：均值 12 tokens

- 数据
- 图文构造方法：
- 爬取90K US专利文件，下载各自的csv，包含专利元数据，如 ID、受让人、发布日期、专利 URL ，使用ID和URL下载**HTML**，解析HTML提取图像URL，下载900K图片
- 专利图片预处理（手动挑选500张图片进行分析,发现很多噪声)----64k专利中获得429k图像：
- 校正图片方向：通过比对原始图像和旋转90°的图像，保存长度较大
- 冗余删除：同一张图像可能在摘要和说明书附图中都出现了，删除摘要中那张图像
- 丢弃多图形图像：大约7%图像中包含多个图形，用ocr提取标签，删除包含多个标签的图像
- 图形/图表删除：通过在300个手动注释图像的子集上训练基于ResNet-50的二进制分类器来丢弃这些图像，实现了98%的验证准确率。
- 公开日期过滤：2004年前发布的专利的标记语言遵守了一个特定的，故放弃了2005年前的专利
- 图文对构造
- brief description
- ocr得到图像的label（例如"FIG. 1")
- 解析HTML，定位\<brief-description-of-drawings> 标签，**等价于“附图说明”**
- 遍历该标签下的每个 \<description-line> 或 \<description-paragraph> 子标签
- detail description
- 继续处理\<brief-description-of-drawings> 之后的description-line/description-paragraph部分，**等价于“具体实施方式”**
- 如果段落以Fig X开头，就任务是对图X的描述，否则就将内容追加到上个图描述的后面
- 存在几个问题：可能一段话同时对多个图片进行了描述
- 结尾段落不针对任何特定图片，可能会错误归属给最后一个Figure
- OCR错误识别（ "FIG. 1" 错识成 "FIG. l"）
- 构造结果的准确性评估
- brief：准确率和召回率：100%
- detail：准确率：90.81%， 召回率：91.96%
- 不足：感觉只抽取了100篇专利中的图片进行手动打标估计，样本量大少

**模型：**

- **PatentMME****：多模态视觉编码器（关键）**

![[PatentLMM image.png]]

- PatentLLama：基于LLama微调的专利大模型
- PatentLMM：通过一个投影层，将PatentMME和PatentLLama结合使用

**模型训练：**

- PatentLMM:
- 半监督训练PatentMME：HUPD数据集
- lora微调LLaMA-2 7B：HUPD数据集
- 两阶段微调PatentLMM：
- 阶段一：只训练映射层，其他冻结
- 阶段二：Lora微调LLaMA，PatentMME冻结
- 视觉检测器：
- 数据集：手工标注400张专利图片，主要框定“节点、节点标签、文本，箭头、图片标签”五个区域
- 350训练，50测试
- ResNet101为backbone，微调F-RCNN

其他：

这个模型主要是为了生成对专利图片的描述，所以构建数据集的时候，使用专利中已有的描述更符合需求。但是在领域多模态的时候，还是需要对这其中的描述进行一定程度的改写的
