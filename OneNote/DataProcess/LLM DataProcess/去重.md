1. 绝对精准去重：哈希方法

哈希函数的核心原理是将任意长度的输入数据，经过一系列复杂的数学运算（如位操作、非线性函数、模加等），映射为固定长度的输出结果（即哈希值或摘要）。

它们具备几个在去重中至关重要的特性：

确定性： 相同的输入，必然得到相同的输出。

碰撞抗性： 极难找到两个不同的输入能产生相同的输出。

雪崩效应（Avalanche Effect）： 输入哪怕发生了一个比特（比如改了一个标点符号）的微小变化，输出的哈希值也会面目全非。

- MD5 ：通过读取文件内容生成一个128bit的指纹
- 数据读取方式：**分块读取**，不断更新哈希对象的装填，所以多大文件都不会撑爆内存
- 相同的文件，只有文件名不一样，MD5值是一样的，因为它只关注文件的内容
- 相同的文件，文件名相同，但是存储的格式不同，一个是pdf，一个是docx，他们的MD5值是不同的。docx到pdf其实经过了一系列的格式转换，所以内容肯定是不同的

- SHA256：通过读取文件内容生成一个256bit的指纹
- 数据读取方式：**分块读取**，所以多大文件都不会撑爆内存
- 去重流程：读取内容 → 计算哈希 → 比对指纹

==🔴局部敏感哈希（Locality-Sensitive Hashing, LSH）：核心目的，如果两个输入内容很相似，那么他们计算出来的哈希值也必须极度相似==

1. 模糊去重：MinHash LSH（通常是基于文件的）
- **n-gram 分解**：将文档视为 n-gram（连续 n 个字符或词）的集合
- 例如："大模型数据" 的 3-gram 集合为 {"大模型", "模型数", "型数据"}
- **MinHash 签名：**MinHash 是一种将集合压缩为固定长度签名的技术。使用 k 个随机哈希函数，为每个文档的 n-gram 集合生成一个长度为 k 的 MinHash 签名向量（通常 k=128）
- 两个集合的 Jaccard 相似度可以通过它们 MinHash 签名的匹配程度来近似估计
- 签名长度越长，估计越准确，但存储和计算开销也越大。
- **LSH 分桶：**
- 将 128 维签名向量分成 b 个 band（每 band 含 r = 128/b 个维度）。两个文档只要在任意一个 band 内的签名完全匹配，就被放入同一个"候选桶"，后续只需对同桶内的文档对进行精确相似度计算
1. SimHash

局部敏感哈希（Locality Sensitive Hashing, LSH）

- **分词：**将待处理数据分成一系列特征词
- **权重分配：**为每个特征词分配权重，通常使用 TF-IDF 算法来确定，核心是能够考虑词的权重
- **生成哈希：**用传统的哈希函数（如 hash()）将每个关键词映射为固定长度的二进制序列
- **加权合并：**
- 如果该位为 1，则加上该词的权重 $W$。
- 如果该位为 0，则减去该词的权重 $W$。
- 将所有关键词加权后的序列按位累加，得到一个长度为 64 的整数序列。
- **降维：**
- 将累加后的整数序列转换回二进制：
- 如果某位结果 大于 0，则记为 1。
- 如果某位结果 小于或等于 0，则记为 0。
- 这个最终的二进制串就是该文档的 Simhash 值。

==🟡Minhash====🟡的数学基础是====🟡Jaccard====🟡相似度==

==🟡Jaccard====🟡相似度：==

文档 A	{"大模型", "模型数", "型数据", "数据清"}

文档 B	{"大模型", "模型数", "型训练", "练数据"}

计算：

交集：A ∩ B = {"大模型", "模型数"} → 2 个

并集：A ∪ B = {"大模型", "模型数", "型数据", "数据清", "型训练", "练数据"} → 6 个

J(A,B)= 6/2=0.333

这里背后的数学定理：两个集合经过哈希后，他们最小哈希值相等的概率，正好等于两个集合的Jaccard相似度：

P(min(h(A))=min(h(B))=J(A,B)

Simhash示例：假设我们有两条短语，并设定 Simhash 长度为 6 位（实际应用通常为 64 位）。

- 待处理短语：
- 短语 A: "我 爱 编程"
- 特征权重: 我(1), 爱(2), 编程(3)
- 第一步：分词与哈希

我们将每个词映射为 6 位二进制码：

- 我: 100101
- 爱: 111000
- 编程: 001011
- 第二步：加权处理

根据权重（w）转换：1 -> +w, 0 -> -w。

- 我 (w=1): \[+1, -1, -1, +1, -1, +1\]
- 爱 (w=2): \[+2, +2, +2, -2, -2, -2\]
- 编程 (w=3): \[-3, -3, +3, -3, +3, +3\]
- 第三步：合并 (按位累加)
- 将上述三个向量的每一位分别相加：
- 第1位: 1 + 2 + (-3) = 0
- 第2位: -1 + 2 + (-3) = -2
- 第3位: -1 + 2 + 3 = 4
- 第4位: 1 + (-2) + (-3) = -4
- 第5位: -1 + (-2) + 3 = 0
- 第6位: 1 + (-2) + 3 = 2

累加结果向量: \[0, -2, 4, -4, 0, 2\]

- 第四步：降维 (二值化)
- 规则：结果 > 0 得 1，结果 \< 0 得 0。
- \[0, -2, 4, -4, 0, 2\] → 001001
- 最终短语 A 的 Simhash 指纹为: 001001
- 相似度判别：海明距离得到两个文档的 Simhash 后，我们通过海明距离（即两个二进制数中对应位不同的数量）来判断相似度。
- 海明距离计算： 对两个二进制值进行 异或 (XOR) 运算，然后统计结果中 1 的个数。判定标准在工程实践中（通常针对 64 位指纹）：如果 海明距离 \< 3，则通常认为两个文档高度相似或重复。

Simhash 关注的是词的权重（比如哪些词更重要），通过加权降维把文本变成一个二进制数字。

MinHash 关注的是词的集合交集，它巧妙地利用了数学概率，用来快速估算两个文本的 Jaccard 相似度。

hash计算过程

填充（Padding）： 首先在原始数据后面补位，使其长度符合特定倍数（MD5和SHA256都是补齐到 512位的倍数）。同时在末尾记录原始数据的真实长度。

分块（Blocking）： 将填充后的数据切分成一个个 512位（64字节）的数据块。

迭代压缩（Compression）： 算法内部有一组初始的“魔法数字”（常量）。每次拿一个 512位的数据块，和上一轮的输出结果进行极其复杂的逻辑运算（包括与、或、非、异或、移位等）。

输出结果： 当所有数据块都处理完毕后，最后生成的那串状态值，就是最终的哈希值。
