- **状态价值函数的作用是对当前策略进行评估。动作价值函数的作用可以看做对于当前状态执行某个动作的评估。**
- **强化学习的目标是找到一个最优策略，这是一个迭代的过程，如何评估策略每次更好了一些，就通过状态价值函数来体现。**
- **我们的目标是在当前策略下根据贝尔曼公式求得所有状态的状态价值，根据状态价值来找到策略提升点从而更新一个新的策略，在这个新的策略下再次计算状态价值，不断迭代，直到状态价值收敛。**
- **最终的最优策略是状态价值收敛，注意最优策略不是唯一的。**

## 1. PPO(Proximal Policy Optimization)
	在PPO的架构里，为了教好一个模型，需要同时维护四个模型--Actor、Reference Model、Reward Model、Critic评判模型
- 1.1 四个模型
	- Actor（需更新参数）
		- 角色：主角
		- 任务：负责根据问题生成答案
	- Reference Model参考模型（冻结参数）
		- 角色：SFT后的原始模型副本
		- 任务：它不参与打分，而是作为约束。
	- Reward Model奖励模型（冻结参数）
		- 一般用什么：直接拿SFT训练好的模型来改
		- 角色：代表人类偏好的判卷人
		- 任务：给Actor说话的结果一个最终的分数
	- Critic评判模型
		- 一般用什么：和Reward一样，也是有Actor同款的Transformer改出来的
		- 和Reward的打分区别在于，它会给每个token一个当下分数
进行一次PPO优化，意味着需要处理4倍同样大的模型，对显存的要求非常大
## 2.DPO（Direct Preference Optimization）
	主要是节省了硬件，只需要维护两个模型：Actor和Ref Model
- 2.1 两个模型
	- Actor：还是需要训练，负责学习
	- Ref Model：依旧保持冻结，负责当参照物，防止模型学偏
	tips：DPO的数据最好是自己改自己的错题集，DPO要想效果好，最好是用当前模型取采样数据，然后让人类（或强模型）去标注好坏
- 2.2 DPO的通点：
	- DPO的成本实际上都转移到数据构造上来了，必须要准备极高质量的偏好对数据，这比纯SFT语料要难收集很多。DPO对数据噪声极其敏感，一旦数据里的“好答案”没有那么好，或者“坏答案”和“好答案”差距不明显，DPO就会立刻把模型带到沟里去
